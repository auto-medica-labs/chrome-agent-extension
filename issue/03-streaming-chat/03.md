# What to build
A streamed chat interface inside the side panel that sends user messages to the active profile’s OpenAI-compatible endpoint and renders incoming tokens in real time. Includes input validation, conversation clear, and stream abort. See PRD sections "Chat — FR-05 through FR-09" and "Non-functional requirements — Privacy".

# Acceptance criteria

- User can type a message and submit it; empty or whitespace-only messages are rejected client-side.
- The active profile’s endpoint, model, and API key are used to initiate a streaming chat completion request.
- Assistant tokens arrive and render incrementally in a scrollable message list (user and assistant bubbles).
- A send button transforms into an abort control while a stream is in flight; clicking abort cancels the request.
- A "Clear conversation" control resets the in-memory message history without reloading the panel.
- No conversation data is persisted to disk or storage in Phase 1 (pure in-memory session).
- The UI remains responsive during streaming (input disabled, scroll stays near bottom).
