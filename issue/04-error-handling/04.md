# What to build
End-to-end error handling for the chat and settings flows. All failure paths surface plain-language messages so non-technical users know what happened and how to recover. See PRD sections "Error Handling — FR-13 through FR-16".

# Acceptance criteria

- Unreachable or invalid endpoint surfaces a "Could not reach the API" message with a retry suggestion.
- Invalid API key or auth failure surfaces an "Invalid API key" message.
- HTTP 429 (rate limit) and 5xx server errors are caught and display a "Retry later" suggestion.
- Streaming interruption (network drop or abort) leaves the partially received response visible in the message list.
- Error messages appear inline in the chat UI or in the settings test-connection area, without browser alerts or console-only output.
- After an error, the user can send a new message or retry without reloading the extension.
