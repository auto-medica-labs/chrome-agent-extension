# What to build
Documentation and architecture validation that enables a new developer to clone, build, and load the extension in under five minutes, and confirms the codebase is structured for Phase 2 extension. See PRD sections "Non-functional requirements — Extensibility" and "Success metrics".

# Acceptance criteria

- `README.md` contains step-by-step instructions for `bun install`, `bun run build`, and loading the unpacked extension in Chrome.
- `AGENTS.md` (or equivalent) documents the component and state boundaries, and identifies where persistence, tool-calling, and DOM context will plug in during Phase 2.
- A fresh clone on a clean machine passes the "<5 minutes to first side-panel render" test.
- Code review confirms state management is chosen to support global injection of tool state and DOM context without prop-drilling rewrites.
- Component boundaries are documented (or self-evident) so a future developer knows where to add a tool-loop or conversation storage layer.
- No structural rewrites are required after this slice merges; remaining Phase 2 work should be additive.
